# MacroMatch 🥗

**Reverse your macros. Build your meal.**

MacroMatch is a full-stack web app that flips the usual "calorie calculator" idea around. Instead of picking a food and checking its macros, you tell MacroMatch the **calories, protein, carbs, and fat you want**, and it searches a food database to find combinations of real foods (with quantities) that come closest to your target — ranked by how good a match they are.

The frontend is plain HTML/CSS/JavaScript. All persistent data — accounts, sessions, foods, pantry, saved meals, logs, and goals — lives in **MongoDB** behind an **Express** API.

---

## ✨ Features

- **Sign up / login** with server-side validation and hashed passwords (bcrypt)
- **Server-side sessions** stored in MongoDB via `connect-mongo`
- **Meal calculator** — enter a macro target and get up to 5 ranked meal suggestions generated by the backend
- **Dashboard** — daily calories/macros, today's meal log, and saved meals
- **Food database browser** — search and filter foods by category, diet, high-protein, or low-calorie
- **Pantry ("Use What I Have")** — mark foods you already have, persisted per user
- **Progress page** — daily goal progress and weekly charts
- **Diet filters** — vegan / vegetarian / non-vegetarian recommendations

## 🚀 Getting started

1. Install dependencies:

   ```bash
   cd backend
   npm install
   ```

2. Add `backend/.env`:

   ```env
   MONGO_URI=mongodb+srv://<user>:<password>@<cluster>/<db>
   SESSION_SECRET=<long random string>
   PORT=5055
   ```

   > On macOS, port `5000` is often occupied by AirPlay Receiver, which is why the
   > default here is `5055`.

3. Start the server:

   ```bash
   npm run dev     # nodemon
   # or
   npm start
   ```

4. Open **http://localhost:5055**. Express serves the frontend and the API from the same origin, so session cookies work without extra CORS setup.

> The food database is seeded automatically on first start. No manual seed step is required.

## 🔌 API

All `/api` routes except auth require an active session cookie. Responses are JSON.

### Auth
| Method | Route | Description |
|---|---|---|
| POST | `/api/auth/signup` | Create an account and start a session |
| POST | `/api/auth/login` | Log in |
| POST | `/api/auth/logout` | Destroy the session |
| GET | `/api/auth/me` | Current user |

### Foods
| Method | Route | Description |
|---|---|---|
| GET | `/api/foods` | All foods; supports `?search=&category=&diet=&mealType=` |
| GET | `/api/foods/:id` | Single food |

### Goal
| Method | Route | Description |
|---|---|---|
| GET | `/api/goal` | Daily macro goal (defaults if unset) |
| PUT | `/api/goal` | Update daily goal |

### Pantry
| Method | Route | Description |
|---|---|---|
| GET | `/api/pantry` | Pantry food IDs |
| PUT | `/api/pantry` | Replace pantry (`{ foodIds: [...] }`) |
| POST | `/api/pantry/:foodId/toggle` | Add/remove a food |
| DELETE | `/api/pantry/:foodId` | Remove a food |

### Meals
| Method | Route | Description |
|---|---|---|
| GET | `/api/meals/log?date=YYYY-MM-DD` | Log entries (all dates if omitted) |
| GET | `/api/meals/log/totals?date=YYYY-MM-DD` | Totals for a day |
| POST | `/api/meals/log` | Add a meal to the log |
| DELETE | `/api/meals/log/:logId` | Remove a log entry |
| GET | `/api/meals/saved` | Saved meals |
| POST | `/api/meals/saved` | Save a meal |
| DELETE | `/api/meals/saved/:savedId` | Unsave a meal |

### Recommendations
| Method | Route | Description |
|---|---|---|
| POST | `/api/recommendations` | Generate ranked meals from a macro target |

Example body:

```json
{
  "calories": 600,
  "protein": 40,
  "carbs": 60,
  "fat": 20,
  "mealType": "lunch",
  "diet": "vegetarian",
  "maxItems": 3,
  "useWhatIHave": true
}
```

## 💾 Data model

| Collection | Purpose |
|---|---|
| `users` | Accounts (`passwordHash`, never returned to the client) |
| `sessions` | Server-side login sessions (`connect-mongo`) |
| `foods` | Seeded food database |
| `goals` | One daily macro goal per user |
| `pantryitems` | Foods marked "at home" per user |
| `meallogs` | Meals logged per user, indexed by date |
| `savedmeals` | Bookmarked meals per user |

The browser **no longer stores application data in `localStorage`**. The only client-side persistence is the session cookie, which is `httpOnly`.

## 🧠 Recommendation engine

Ported to `backend/lib/recommendationEngine.js` and executed on the server:

1. Filter foods by diet, meal type, and pantry (if enabled).
2. Build a candidate pool sorted by protein-per-calorie.
3. Generate combinations of 1..`maxItems` foods.
4. Scale portions (nearest 25 g / half-piece) and score each combo:

   ```
   score = 0.30 × calorieMatch + 0.35 × proteinMatch + 0.20 × carbMatch + 0.15 × fatMatch
   ```

5. Flag combinations within ±8% of every target, rank them, and return the top 5.
